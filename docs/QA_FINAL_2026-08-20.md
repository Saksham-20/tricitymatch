## Bugs found and fixed

### 1. Filter sheet stayed open across tab switches (both platforms) — FIXED

Opening Search's filter sheet and then switching tabs left the sheet open. Every
later visit to Search opened with the filters covering the results instead of the
profile list. The tab navigator keeps `SearchScreen` mounted and gorhom's
`BottomSheet` holds its own position, so nothing ever closed it.

Fixed by closing the sheet on blur (`useFocusEffect` in `SearchScreen.tsx`).
Commit `638a748`.

Verified live on Android and iOS: Search (closed) → open filters (open) → Home →
back to Search (closed).

> Method note: the first iOS attempt appeared to fail. The simulator was running a
> stale JS bundle from before the edit — a debug build does not pick up a change
> until it reloads. Force-quit and relaunch before believing a negative result.

### 2. Floating tab bar covered the filter sheet's own buttons (both platforms) — FIXED

The pill tab bar is `position: absolute` over the whole screen, so it drew on top
of the open filter sheet. On Search that put it directly across **"Save search"**
and **"Show N profiles"** — the sheet's only way to apply a filter. Present on iOS
and Android alike; caught from the screenshots, not the accessibility tree, since
both controls are still *present* in the tree, just covered.

Fixed with an ephemeral `bottomSheetOpen` flag in `uiStore`, set by `FilterPanel`
and read by `FloatingTabBar`, which now hides for a sheet the way it already hid
for the keyboard. Elder mode is unaffected (it uses the docked bar). Commit
`da82906`.

Verified live on both: sheet open → tab bar hidden, both CTAs fully visible; sheet
closed → tab bar returns. The sheet remains dismissible while the bar is hidden
(pan-down on iOS, hardware back on Android), so there is no trap.

The web equivalent is already correct — its mobile filter sheet sits at `z-[60]`
above the `z-50` nav, and "Apply Filters" is unobstructed at 375px
(`web-13-mobile-375-filters.png`).

## Known limitation (documented, not fixed)

**Android "Share PDF" for the marriage biodata shares only a text caption.** React
Native's `Share.share()` accepts `url` on iOS only; on Android it silently drops it
and shares just `message`, so the share sheet opens titled "Sharing text" and the
recipient never receives the PDF. iOS is unaffected.

The fix is `expo-sharing`'s `shareAsync()`. It was attempted and reverted: npm
hoists the package to the workspace root, so the rebuilt APK picked up its
FileProvider resources but not the JS module registration — `require('expo-sharing')`
resolved to `undefined` at runtime and the code silently fell back anyway. That is a
monorepo autolinking change, not a launch-day patch. The reasoning is recorded in
`mobile/src/hooks/useBiodataShare.ts` so the next person does not rediscover it.

## Not a bug

- **"9999 unlocks remaining" on ProfileDetail while the dashboard says "Unlimited
  Unlocks".** The QA account's VIP row has `contactUnlocksAllowed = 9999`
  hand-written into the dev DB. The real unlimited sentinel is `NULL`, which the
  backend maps to `-1` and the UI renders with no count at all. Other VIP rows in
  the same table are correctly `NULL`, and no code path writes 9999. Dev-seed
  artifact only.
- **"5000 new Tricity profiles joined this week"** on Home. Checked against the
  database: the dev corpus genuinely holds 5,060 users with 5,002 created in the
  last seven days. The counter is reporting truthfully.
